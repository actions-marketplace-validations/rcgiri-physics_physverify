# Rescan of the tested repositories with `physverify scan` (2026-10-23)

Every repository cloned for batches 1 to 8 (626, including those that were drawn but not tested) was scanned with `physverify scan` twice: at the commit that was tested, and at the latest commit of its default branch, fetched on 2026-10-23. The scan only reads the source; nothing was run. Repositories are named by ID.

The counts describe these 626 repositories only. They are not a bug rate, and since the scan's rules were adjusted on this same sample (see "Rules changed during the rescan"), the false-alarm count below is optimistic for code it has not seen.

## How detection grew during the rescan

The scan was improved four times on 2026-10-23. Each row is the whole corpus scanned again with that version. "Of the 74" is how many of the defects already reported to authors it finds with no test script; "new" counts defects not reported before, each confirmed later by a run in the sandbox.

| Version | What it added | Of the 74 | New defects | False alarms after triage | Time per commit set |
|---|---|---|---|---|---|
| 1. First scan | constants, literal Runge-Kutta tables, grid spacing against `linspace`, inverse pairs | 2 (H19, K26) | 0 (plus the RK53 typo already sent to F09) | 2 grid (H33, K03); 34,101 constant notes | about 21 min |

## Runge-Kutta stages written as code (added the same day)

A second pass read the steppers whose stages are written as code (`k2 = h*f(t + h/2, y + k1/2)`), and a third the tables passed to constructors or inherited in classes. In the final rescan the tables stage has 13 WARNs at the tested commits in 3 repositories (F09, E09, J042) and 9 at the latest commits (F09 has fixed its four); every one is a real defect:

| ID | Function | What the scan says | Confirmed by a run (sandbox) |
|---|---|---|---|
| J042 | `heun`, `rk38`, `bs` in `ode.py` | stage time, missing stage, weights differ from the docstring table | **known defects, recovered** (reported earlier, still open) |
| J042 | `ode4` in two n-body examples | weights 1/3, 1/6, 1/6, 1/3 differ from the docstring's 1/6, 1/3, 1/3, 1/6: order 2 | **new**: measured order 2.03 (control `rk4`: 3.87) |
| E09 | `heun3` | stage 3 fed with `k1` instead of `k2`: order 2 | **new**: measured 2.14 for a claimed 3 |
| E09 | `exp_rk4` (the sampler's `'rk4'`) | stages 3 and 4 fed with the wrong earlier stage: order 1 | **new**: measured 1.03 for a claimed 4 |
| E09 | `exp_tsit5` (`'tsit5'`) | stage 4 fed with `k3`; four stages leave out `h` | **new**: does not converge (error 0.43 at every step size) |
| E09 | `Tsit5()` table | `b_error` sums to 0.97 | **known defect, recovered** |
| F09 | `RK32`, `ARK343ERK`, `ARK548L2SAESDIRK`, `RK53` | order labels, embedded order, row sum | known, fixed upstream |

The first version of this pass also flagged six correct steppers (J138, J442: autonomous `f(state, params)`; J178, J263, J352: systems advanced in two parts). The rules were changed (a stage time without `h` is compared only with a table that states it; split systems are skipped), and the sample was scanned again. At the latest commits 8 WARNs remain, in E09 and J042.

## Rules changed during the rescan

The first pass had 19 grid WARNs and 34,101 constants NOTEs. Each change below was made after reading the findings, then the whole sample was scanned again:

1. **Constants:** pure numbers (π, e, 4π², the Ising T_c) are noted only within 0.2%, not 10%, and `g` only when assigned to a gravity-like name; repeats in a file are one line. 34,101 → 678.
2. **Grid, size of the grid:** the denominator must differ from M − 1 by a constant. Removed an element length `L/n` next to a plot grid of `100 n` points (H33).
3. **Grid, scope:** a spacing and a grid in different functions are a NOTE, not a WARN (J023, K40: real but between methods).
4. **Grid, slice steps:** a division used as the step of `np.mgrid[a:b:step]` is its own grid (K03).
5. **Tables, stated order:** `order = 3` or `def order(self): return 3` in the class counts as the claim, before the docstring (recovered F09 RK32).
6. **Robustness:** five large libraries stopped the scan on unusual literals (`np.array(...) / 2`, huge integers); fixed, and one stage failing on one file no longer stops a project scan.

## Run time

About 26 minutes for each of the two scans (626 and 625 repositories), on one core each; the slowest repository (a large library with 200 files) takes about 30 s. Caching the syntax-tree walks made the large libraries 30 to 40% faster.

## How to repeat it

The clone script and the rescan driver are in the private study folder (`physverify_private/corpus/rescan/`: `fetch_latest.sh`, `rescan.py`); the outputs are one JSON line per repository. They will be published with the repository names once the authors have been told.
